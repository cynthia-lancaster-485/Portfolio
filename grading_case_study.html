A gradebook built
secure by design.

Over a semester at the University of Utah, I built a complete grading system in Django: three kinds of users, PDF uploads, weighted grades, and a deployment to AWS with my own domain and HTTPS. Later I came back to it, found the bugs a class autograder never checked, fixed them, and added automated tests.

The stack

One framework, every layer.

Django handled the database, the pages, and authentication, which let me focus on the rules that make a gradebook trustworthy: who can see what, who can change what, and what counts toward a grade.

🐍
Backend
Python / Django

Models, views, and validation, with every permission rule kept in one place on the model.

🖥️
Frontend
Templates + JavaScript

Server rendered pages, plus JavaScript for sorting, async uploads, and a live grade calculator.

🗄️
Database
Django ORM

Efficient queries, like picking the least busy TA in a single query instead of a loop.

☁️
Deployment
AWS EC2

Ubuntu server, NGINX reverse proxy, a custom domain, and HTTPS through Let's Encrypt.

What it does

Three roles, one gradebook.

Students

Upload, track, and plan

Upload a PDF before the deadline, see every grade, and use the "what if" calculator to see what a score on upcoming work would do to the final grade.

TAs

Grade only what's yours

Each new submission goes automatically to the TA with the fewest for that assignment, and each TA sees and grades only their own queue.

Instructor

See everything

The instructor sees every submission, can grade any of them, and tracks overall grading progress.

Accessibility

Sortable tables for everyone

Column headers sort by mouse or keyboard and announce their sort state to screen readers with aria-sort.

Security

  
Never trust the browser.

  
The hardest part of this project wasn't the features. It was making sure nobody could do what they shouldn't. Every limit in the page is repeated on the server, because anyone can edit a form or send their own request.

  

    

      
🔒

      

        
One source of truth

        
Permission checks live in model methods, so the grading page, the form handler, and the file download all enforce the exact same rule.

      

    

    

      
🛡️

      

        
Crafted requests fail

        
A TA who edits the form to grade a submission that isn't theirs gets an error, not a changed grade. Students get a 403 on the grading page.

      

    

    

      
📄

      

        
Uploads are checked twice

        
A file must end in .pdf and start with the real PDF signature. The 64 MiB limit is checked before reading the file, and files are checked again on download.

      

    

    

      
↩️

      

        
No open redirects

        
After login, the app only follows a "next" link back to its own site, so a phishing link can't bounce users somewhere else.

      

    

  










  
Revisiting my own code

  
Coming back with fresh eyes.

  
When I moved this project from my school account to my own, I ran it end to end instead of trusting that it passed the class autograder. I found real bugs, fixed each one in its own commit, and wrote tests so they stay fixed. The first commit in the repo is the code exactly as I submitted it, so the before and after are both there to see.

  

    
21
automated tests covering login, uploads, permissions, grading, and grade math

    
15
of those tests fail on the original code, so they catch real bugs

What I learned

    
Security is a design decision.

    

      

        
01

        
Where a rule lives matters

        
Putting permission checks on the model meant one rule protected every page that used it, instead of hoping each page remembered to check.

      

      

        
02

        
The server is the last line of defense

        
Limits in the HTML make a form friendlier, but only checks on the server make it safe. Good UX and good security turned out to be the same work.

      

      

        
03

        
Tests find what you missed

        
Writing tests later surfaced bugs I had shipped without noticing. Now I check my work by trying to break it, not just by watching it work.
